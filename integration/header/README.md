# Оптимизация шапки

## Установка

1. Скопируйте содержимое `preload-head.html` в «HTML-верх»/поле кода внутри `<head>`, по возможности до таблиц стилей и остальных скриптов. Важно: блок должен находиться в настоящем `<head>`, а не только вверху тела страницы. Если административная форма не даёт разместить код до CSS, preload всё равно стоит поставить как можно раньше; его фактическое время загрузки нужно проверить в DevTools.
2. Замените старый HTML шапки целиком содержимым `header-optimized.html`. Не подключайте обе версии одновременно.
3. HTML шапки оставлен прежним, включая ссылки, классы и содержимое. Файл не меняет размеры, фоны и анимации из текущих CSS.

## Изменения

- Загрузка изображения выбранной темы начинается из head. Встроенный preload в HTML шапки оставлен как безопасный fallback: одинаковый id предотвращает повторное создание ссылки.
- Первая сборка шапки запускается сразу; DOMContentLoaded используется для повторного идемпотентного прохода, если меню ещё не было разобрано браузером.
- Уже размещённое меню повторно не перемещается.
- Наблюдатель переноса переключателя темы отключается после переноса; если переключатель отсутствует, наблюдение прекращается через 10 секунд.
- Измерения фона объединяются через requestAnimationFrame.
- Светлячки добавляются одним DocumentFragment в свободное время браузера после кадра; при prefers-reduced-motion декоративная работа пропускается.

## Проверка

Chromium: светлая/тёмная тема, 390 и 1280 px, ранняя сборка до DOMContentLoaded, одна preload-ссылка на правильный фон, позднее появление меню/переключателя темы, раскрытие/сворачивание, смена ширины, 24 светлячка, reduced motion, отсутствие JS-ошибок. Оба inline-скрипта прошли node --check.

Исходный trace: LCP 5,254 с, обнаружение фона шапки около 4,189 с. Итоговый LCP после установки не измерен. Большие и поздно импортируемые CSS остаются отдельной задачей; эти изменения не обещают устранить всю задержку загрузки.
